# API Specification & Frontend Client Guide

## 1. FastAPI REST API Specification

The backend service (`app/main.py`) exposes RESTful endpoints for part configurations, real-time NC inference calculations, and audit history retrieval.

### Endpoint Overview

| Method | Endpoint Path | Description |
|---|---|---|
| `GET` | `/health` | Server health check |
| `GET` | `/api/config/parts` | Returns list of registered Part Numbers |
| `GET` | `/api/config/details/{part_number}` | Fetches default nominal parameters for a part number |
| `POST` | `/api/prediction/calculate` | Calculates $NCTr$ recommendation & saves audit log |
| `GET` | `/api/prediction/history` | Retrieves complete prediction audit history |
| `DELETE` | `/api/prediction/history` | Clears all prediction history records from database |

## 3. Vite-React Frontend Client Architecture

The web dashboard (`frontend/src/App.jsx`) is built with React 18, Vite, and TailwindCSS v4:

- **Interactive Parameters Dashboard**:
  - **Left Column**: Part Number drop-down selector with dynamic preview (fetching default resistance, sensor type, and NT step flags), Sputter machine parameters, and substrate pre-test inputs.
  - **Right Column**: Interactive Visualizations Dashboard with 3 Tab Views:
    1. **Tolerance Gauge**: Multi-zone range bar displaying $R_{\text{nominal}}$ vs pre-trim $R_{20}$ vs post-trim predicted resistance relative to IEC 60751 tolerance bands (F 0.1, F 0.15, F 0.3).
    2. **Feature Impact**: Parameter contribution breakdown bars showing relative impact magnitudes of film thickness, TCR, sheet resistance, and humidity on the $NC$ recommendation.
    3. **Yield Confidence**: Predicted selection yield probabilities across tolerance classes.
- **Audit History Log Table with One-Click Clear**:
  Renders prediction runs saved in SQLite/Supabase, with a trash action to clear history (`DELETE /api/prediction/history`).

## 4. Automated Verification Test Suite (`test_api.py`)

The test script `backend/test_api.py` verifies the FastAPI server end-to-end:

```bash
python test_api.py
```

### Verified Test Cases:
1. `GET /health`: Asserts `status == "ok"`.
2. `GET /api/config/parts`: Asserts registered part numbers exist.
3. `GET /api/config/details/{part_number}`: Asserts correct default parameter mapping.
4. `POST /api/prediction/calculate` (Full Inputs): Validates prediction output and compliance disclaimers.
5. `POST /api/prediction/calculate` (Omitted Inputs): Verifies dynamic database average fallback calculation.
6. `GET /api/prediction/history`: Asserts history log persistence.
7. `DELETE /api/prediction/history`: Asserts prediction history wipe functionality.
